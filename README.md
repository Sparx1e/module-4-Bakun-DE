# ФормаДесерт — приложение магазина кондитерских принадлежностей

**Название приложения:** «ФормаДесерт» (компания-заказчик — «ФормаДесерт»).
Версия: 1.0.0.

## Назначение и основные функции

Настольное приложение для демонстрационного экзамена по компетенции
«Информационные системы и программирование». Приложение автоматизирует
работу интернет-магазина кондитерских принадлежностей: ведёт каталог моделей
товаров, позволяет клиенту оформить заказ, а менеджеру и администратору —
просматривать, создавать, изменять и удалять заказы.

Реализованные модули:

* **Модуль 2 — каталог.** Загрузка моделей товаров из PostgreSQL, вывод
  изображения, категории, наименования, производства, состава, цены со
  скидкой и суммарного остатка по всем вариантам исполнения. Для моделей без
  заказов за предыдущий календарный месяц относительно проверочной даты
  `20.10.2026` действует скидка 25 %. Модели с остатком ≤ 3 подсвечиваются
  светло-красным (`#FF8080`). При отсутствии файла изображения выводится
  заглушка `resources/images/picture.png`.
* **Модуль 3 — последовательный интерфейс и оформление заказа.** Вход по
  логину без пароля, отображение ФИО в правом верхнем углу, переходы между
  страницами и возврат назад, сортировка по цене, фильтр по категории,
  мгновенный поиск по наименованию и описанию, карточка товара с выбором
  варианта и количества, корзина с изменением количества и удалением позиций,
  подтверждение заказа с сохранением цен и уменьшением остатков.
* **Модуль 4 — работа с заказами для менеджера и администратора.** Список
  заказов с датой и ФИО клиента, просмотр состава, создание заказа с поиском
  товара, удаление заказа с подтверждением и возвратом товаров на склад,
  редактирование заказа администратором (дата и удаление позиций), обновление
  списка после каждой операции.

## Подготовка базы данных

1. Установите PostgreSQL 18 и убедитесь, что служба сервера запущена.
2. Создайте базу данных и загрузите структуру с данными. Скрипт
   [`db/database.sql`](db/database.sql) идемпотентен: он удаляет и заново
   создаёт схему `public`, поэтому его можно выполнять повторно.

   ```powershell
   # Вариант 1: автоматический скрипт (запросит пароль)
   powershell -ExecutionPolicy Bypass -File scripts\setup_db.ps1

   # Вариант 2: вручную
   createdb -U postgres -h localhost -p 5432 formadessert
   psql -U postgres -h localhost -p 5432 -d formadessert -f db\database.sql
   ```

3. Проверьте загрузку:

   ```sql
   SELECT COUNT(*) FROM products;      -- 24
   SELECT COUNT(*) FROM stock_items;   -- 48
   SELECT COUNT(*) FROM orders;        -- 18
   ```

## Настройка подключения

Параметры подключения читаются из переменных среды. Пароль в исходном коде
не хранится.

| Переменная | Значение по умолчанию |
| --- | --- |
| `PGHOST` | `localhost` |
| `PGPORT` | `5432` |
| `PGDATABASE` | `formadessert` |
| `PGUSER` | `postgres` |
| `PGPASSWORD` | пустая строка |

Можно скопировать [`.env.example`](.env.example) в `.env` рядом с проектом и
указать свои значения. Файл `.env` добавлен в `.gitignore` и не попадает в
репозиторий.

Пример для текущей сессии PowerShell:

```powershell
$env:PGHOST = "localhost"
$env:PGPORT = "5432"
$env:PGDATABASE = "formadessert"
$env:PGUSER = "postgres"
$env:PGPASSWORD = "ваш_пароль"
```

## Запуск приложения

```powershell
python -m pip install -r requirements.txt
python -m app.main
```

или:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run.ps1
```

При недоступности сервера приложение показывает информативное сообщение об
ошибке подключения и не завершается аварийно.

## Сборка исполняемого файла

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_exe.ps1
```

Результат: `dist\FormaDessert\FormaDessert.exe`.
Собранная версия использует те же переменные среды и файл `.env` рядом с
исполняемым файлом.

## Учётные записи для проверки

Пароль не требуется — вход выполняется только по логину.

| Логин | ФИО | Роль |
| --- | --- | --- |
| `admin` | Миронов Алексей Игоревич | Администратор |
| `manager` | Лебедева Мария Олеговна | Менеджер |
| `client1` | Соколов Иван Александрович | Клиент |
| `client2` | Кузнецова Анна Сергеевна | Клиент |
| `client3` … `client6` | клиенты из `Users_import.csv` | Клиент |

## Проверочные сценарии

1. **Каталог и скидка.** Войти как `client1`. У моделей без заказов за
   сентябрь 2026 отображается цена со скидкой 25 % и подпись о скидке.
   Модели с остатком ≤ 3 (например, № 1 и № 2) подсвечены `#FF8080`.
2. **Поиск, фильтр, сортировка.** Ввести в поиск `форма`, выбрать категорию
   «Формы для выпечки», переключить сортировку по цене. Результаты
   обновляются сразу, выбранная сортировка сохраняется.
3. **Оформление заказа.** Открыть модель, выбрать вариант и количество,
   добавить несколько позиций, изменить количество, удалить позицию,
   подтвердить заказ. Остаток в каталоге уменьшается, заказ сохраняется.
4. **Ограничения.** Попытаться добавить количество больше остатка или
   подтвердить пустой заказ — появляется предупреждение, данные не меняются.
5. **Заказы менеджера.** Войти как `manager`, открыть «Заказы», просмотреть
   состав, создать заказ с поиском товара, удалить заказ — остатки
   возвращаются на склад, список обновляется.
6. **Права администратора.** Войти как `admin`. Кнопка «Изменить» доступна
   только администратору: можно изменить дату заказа и удалить отдельные
   позиции; остатки пересчитываются.
7. **Ошибка БД.** Остановить службу PostgreSQL и запустить приложение —
   выводится сообщение о невозможности подключения, аварийного завершения нет.
